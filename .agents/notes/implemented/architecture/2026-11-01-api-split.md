# Agent Note: api.py 按资源拆分 (单文件上限 500 行)

Status: implemented

## Problem

`packages/browser/src/hx_browser/api.py` 706 行, AGENTS.md 要求单文件 <=500 行. 之前的 "只降不涨" 棘轮不构成豁免.

## Decision

按资源切成独立路由文件, 每个文件自带 `APIRouter(prefix="/api/v1")`:

- `api_common.py`: `manager()` / `store()` / `ok()` / `fail()` 与 `_manager` 单例.
- `api_system.py`: `/status`, `/settings`, `/orphans`, `/orphans/cleanup`, `/logs`, `/groups`.
- `api_env_ops.py`: 单个环境的读, 改, 删, 批量, 复制, 启动, 停止, 状态, 以及 `/environments/login-states`.
- `api_packs.py`: 账号包导入导出, profile 导入, cookie, 缓存清理, 指纹检测.
- `api_resources.py`: 代理, 模板, 扩展.
- `api.py`: 只剩 `create_app`, 按原顺序注册路由与中间件; 再导出 `manager` / `store` / `ok` / `fail` / `start_env` 保持旧导入路径.

注册顺序: api_envs, api_folders, api_system, api_env_ops, api_packs, api_resources, 其后 api_profiles, api_live, api_hxcp, api_fingerprint, mcp 不变. 函数体原样搬迁, 没有改行为.

## Alternatives considered

- **只把最长的几段挪走凑到 500 行**: 文件边界没有含义, 下次加路由又会超. 按资源切.
- **一个共享 router 由各模块往上注册**: 依赖导入顺序决定路由顺序, 隐式且易碎. 改为 create_app 显式 include.

## Consequences

- 同一 HTTP 方法下会互相遮挡的路径 (如 `/environments/login-states` 与 `/environments/{env_id}`) 保留在同一文件且相对顺序不变. 拆分前后路由集合逐条对比一致 (72 条), 存在遮挡关系的路由对相对顺序无变化.
- 测试重置单例改为 `api_common._manager = None`.
- 2026-11-01 单文件上限调为 500 行后仍保留本拆分, 不回退: 原 api.py 706 行同样超 500; 拆后各文件最大 222 行, 边界按资源有含义, 加路由有余量; 合回去要重排 72 条路由的注册顺序, 有风险没收益.
