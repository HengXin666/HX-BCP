# Agent Note: 人机双通道准入分离

## Problem

人与 Agent 共用同一套浏览器与代理组件时, 会话混在一起: 排障分不清"我点的"和"程序点的";
更实际的风险是, 若 Agent 能操作人类会话, 它就等于拿到人在浏览器里的登录态。

## Decision

两条通道, 准入门槛不同, 且互不顶替:

- 人类通道: 需要**本机生成**的人类令牌 (只落 `~/.bcp/human.token`, 权限 0600), 令牌不进仓库、不进 Agent 环境。
- Agent 通道: 每个请求必须带项目名 (参数或 `X-BCP-Project`), 缺失直接 400; 项目名即原生分组键。

判据只有一处: `packages/lane/lane.py` 的 `decide()`, 接口层、控制台、CLI 全部引用它。

## Alternatives considered

- **什么都不做, 共用一个通道**: 省事, 但会话无法区分来源, 且 Agent 天然获得人类会话的操作权, 排障与安全都无法收敛, 所以否决。
- **复用现成 RBAC / 角色表**: 使用者只有"这台机器上的人"和"某个项目的程序"两类, 维护用户表与权限矩阵的成本远大于收益; 用令牌与项目名两个事实就能判定。
- **给 Agent 也发长期令牌**: 等于让程序持有与人等价的身份, 泄露面更大; 项目名是更低成本且可审计的分组键。
