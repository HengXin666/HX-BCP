# Agent Note: 指纹保真用同机多路对测判定, 判据只认顺序无关量

Status: implemented

## Problem

判断"某层代理是否改变了客户端的握手身份"时, 有三种都在本仓库出现过的错误做法:

1. **看代理自己的日志/配置** —— 代理报告"我用的是 chrome146 指纹"是**实现声明**, 不是站方读数;
2. **用顺序敏感量判等 (ja3_hash / ja4)** —— 实测同一浏览器连打 6 次, `ja3_hash` **6/6 各不相同**:
   Chrome 对 ClientHello 扩展顺序做**逐连接随机置换**。拿它判"两路是否相同"必然失败;
3. **抓不到读数就跳过** —— 路测不通时旧逻辑把该路从对照里过滤掉, 于是剩下的路全绿、裁决 GREEN,
   一条**完全没被测试**的路被报成"与真身完全相同"。
   (2026-09-17 首跑真实撞到: mitm 路因代理未起来返回 ERR_PROXY_CONNECTION_FAILED, 旧逻辑给了 GREEN。)

## Decision

`workspaces/browser-auto/fp-audit/fp_ab.py` + `probes/tls.py` 把这件事做成一条**可回归的判据**:

- **同机多路对测**: 同一台机器、同一浏览器、同一批参数, 唯一变量是**走不走代理**。
  差异因此唯一归因于被代理的那一层。
- **只认顺序无关量判等**: `ja3n_hash` / `ja4_r` / `akamai_hash` (实测跨连接 STABLE)。
  顺序敏感量 (ja3_hash/ja4/ja4_o/ja4_ro) **只记录不判等**, 并在报告里显式标注"不参与判等"。
- **先查同路自稳性再跨路比对**: 同路自己在多次采样间不稳 → 直接判 `invalid`, 不产出任何"一致"结论。
- **无读数一律判红**: 任何一路取不到读数, 先报 S0 红项; 有效路数 < 2 则整份裁决 `invalid`。
  静默跳过一条路 = 把"没测"包装成"通过"。
- **路是可配置的**: `--arms "direct,tunnel=URL|flag,mitm=URL|flag"`,
  判据不绑定任何具体实现 —— 换候选实现只改一行参数。

## Alternatives considered

- **只用一次请求对比** (最强理由: 省时, 且 `ja4_r` 本身就是顺序无关的, 单次也读得出来)。
  否决: 单次无法发现"同路自不稳"(端点被 CDN 改写、代理抖动、缓存串味), 而这类噪声
  会被误读成"两路不同"。自稳性检查是跨路比对的前提, 没有它比对无意义。
- **沿用 `ja3_hash` 作为主判据** (最强理由: 它是业界最广为人知的指纹标识, 报告可读性强)。
  否决: 实测 6/6 逐连接不同, 用它判等会产出**假红** (真身 vs 真身也不等) 或
  在固定顺序的实现上产出**假绿**。它在报告里保留, 但明确标注"不参与判等"。
- **什么都不做 / 靠人工看代理日志** (最强理由: 零成本, 且本仓库过去几个月就是这么做的,
  也确实发现了 E2 那条问题)。
  否决: 它发现的 E2 恰好是**误读** —— "cacheproxy 自己会崩"实为 shutdown 顺序 bug,
  服务期正常。人工读日志无法把差异定位到"丢了哪一个扩展", 而这次对测直接锁定了 `51764`。

## Consequences

**买到的**: 判据能在无人值守下回答"这层代理有没有改身份", 并把差异定位到**单个扩展**。
实测已把 MITM 的差异锁定为缺 `51764` (0xCA34, RFC 8701 的第二个 GREASE 值) 与
`ecdsa_secp256r1_sha256`; 而 tunnel 路的扩展集合 (`0,5,10,11,13,16,18,23,27,35,43,45,51,17613,51764,65037,65281`)
与真身**逐项相同**, 且 12 次采样下随机性形状也逐项相同 (`ja3_hash`/`ja4_o`/`ja4_ro` 均 12/12 随机,
`ja3n_hash`/`ja4_r`/`akamai_hash` 均 1/12 恒定)。

**代价 (两半都要说)**:

- **外部端点依赖**: 判据读 `tls.browserleaks.com/json`。该站改版或不可达即失效,
  需切 `tls.peet.ws/api/all` (字段更全, 多一层解析)。
- **只覆盖"客户端 → 站方"这一侧**: 不测服务端侧保真度。
- **不覆盖 TCP/IP 层**: `tls.peet.ws` 的 `tcpip` 段已暴露 TTL / SYN 选项 / 窗口等, 本轮未纳入判定。
- **仍是集合级**: 集合相同不等于逐字节相同 (padding、key_share 尺寸、TLS 记录分片未覆盖)。
  提到 10~12 次采样比对**随机性形状**只是缓解, 不是形式化证明。
- **同出口盲区**: 未做跨机器/跨出口对照 —— 同一出口下 `akamai_hash` 恒定有可能掩盖出口侧改写。
- 全套判定跑一轮约需 3~5 分钟 (含起停浏览器), 不适合放进最短的提交前钩子。
