# Agent Note: hxcp 挂载按环境串行，日志不走管道

Status: implemented

## Problem

hx-browser 把 hxcp 当可选子进程挂到浏览器环境上。两件事实让这个进程管不住：

同一环境的两次 `start()` 可以同时通过「还没登记」的检查，各起一个进程，后写进 `_RUNNING` 的那条把前一条盖掉。被盖掉的进程不再有人 `stop()`，环境关掉或服务退出都留着它。

`start()` 把 stdout 接到 `PIPE`，唯一的读者是当时那个服务进程里的线程。hxcp 用新会话脱离了父进程，服务重启后它还活着，管道的读端却没了。之后每次 `print`（新标签页挂上时、每小时的统计）都抛 `BrokenPipeError`，新页挂不上，主循环也会因此退出。接管到的进程等于已经坏了。

## Decision

同一环境的 `start()` / `stop()` 共用一把可重入锁，检查现有挂载、拉起进程、登记、停止都在这把锁里做完。第二个启动会看到已经登记的进程，不再另起一个。别的环境用自己的锁，不会被这次等待挡住。

stdout 和 stderr 追加写入该环境缓存目录下的 `hxcp.log`，不再使用管道。`_wait_ready` 只认启动前记下的文件偏移之后新出现的「已挂载」。服务重启后被接管的 hxcp 继续往同一个文件写，不依赖原来的服务进程还活着。

## Alternatives considered

- **只在 async 包装层加锁** — 调用点集中。否决：`mount_if_enabled` 直接调 `start()`，锁放在包装层盖不住这条路径，也盖不住 `start()` 内部再调 `stop()`。
- **在 hxcp 里吞掉 BrokenPipeError** — 改动小，进程不会因为打印退出。否决：新标签页的挂载日志被吞掉时，失败和成功分不清；统计输出也没了。日志文件保留这些输出，并且不把生命周期绑在父进程的管道上。
- **服务重启时直接杀掉再拉起 hxcp** — 避免接管一个写不了 stdout 的进程。否决：浏览器还开着，重启服务不该把缓存代理打断一次。日志文件让原来的进程可以继续被接管。

## Consequences

- 同一环境的启动不再并发。环境之间各用各的锁，一个环境等 CDP 时不挡住另一个环境。
- 缓存目录里多一个 `hxcp.log`，随 `drop_cache` 一起删掉。彻底删除环境时日志不另留。
- 就绪判定只看本次启动之后的日志。旧文件里已经有的「已挂载」不会被当成这次已经挂上。

## Testing

`services/hx-browser/tests/test_hxcp_race.py` 钉住三件事：两个线程同时启动只留下一个进程、启动过程中的停止会在登记之后收掉该进程、stdout 是缓存目录里的日志文件而不是管道。`test_hxcp_link.py` 仍覆盖缓存隔离和 PID 身份。
