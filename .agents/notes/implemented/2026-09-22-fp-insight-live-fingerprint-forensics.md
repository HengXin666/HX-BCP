# Agent Note: 指纹取证做实时钩子观测, 而不是事后静态分析

Status: implemented

## Problem

写逆向脚本最贵的一步不是"绕过", 而是**不知道要绕过什么**。本仓库在此反复付出代价:

- **2026-09-14**: 改指纹时才发现「换 seed 其实没换指纹」—— 三个 seed 的
  `platform/UA/cores/screen/WebGL` 6/7 完全相同。
- 同一周: 判"环境行不行"靠临时脚本 + 人眼看输出, 不同会话判据不一致, 无法回归比对。

已有的 `fp-audit/` 解决的是**自检**("我这环境干净吗"), 它跑第三方站点拿红黄绿。
但它回答不了另一个方向的问题: **这个目标站点到底在看什么**。
逆向工程师需要的是"哪一行代码读了我的 canvas", 而不是"我有没有被认出来"。

## Decision

新建 `workspaces/browser-auto/fp-insight/` —— 通用**指纹取证**工具, 独立于 fp-audit:

- `inject.js` 页内探针 (127 个观测点), 经 CDP `Page.addScriptToEvaluateOnNewDocument`
  在**文档创建之前**落地, 保证站点自己的采集脚本跑之前钩子已就位。
- **只观测, 不改写**。不伪造返回值, 不自动接受弹窗。
- 证据形态是**调用栈** —— 栈顶第一帧即逆向入口, 直接回答"在哪一行"。
- **变量纠察**: 对每个被观测值做差分, 区分"恒定"(认人锚点) 与"N 变体"(自然变化)。
- `hub.py` 单写线程 SQLite; 计数以**绝对快照 + MAX 合并**入库 (幂等, 容忍重复与乱序)。

## Alternatives considered

**什么都不做, 用现成的 fingerprintjs / creepjs 读自己的结论。**
最强理由: 那些库已经把人脸、时区、canvas 都算好了, 拿来就用, 零开发;
而且 `fp-audit/` 已经在跑它们了。
**否决**: 它们给的是**对自己的判定**("你是 bot"), 不是**对目标的观测**("目标在读你的什么")。
逆向工程师要的是后者, 且要精确到源码行 —— 现成库一条都不给。
更关键的是, 那种一站式的库本身就要注入一大坨 JS, **它自己**会污染被测环境。

**把观测做在 Puppeteer/Playwright 的 `page.evaluate` 里。**
最强理由: 写起来最短, 不用碰 CDP 协议细节。
**否决**: 读 DOM 时经过的每个属性访问都会命中自己的钩子, 变量纠察立刻被自己的读数污染 ——
工具会把自己读到的值当成"站点采集行为"报告出来。
**这是本轮实测踩到的真问题** (修法见下), 不是理论担忧。

**用代理对象包住整个 `window.navigator` 做拦截 (Proxy 模式)。**
最强理由: 覆盖面最广, 连没预料到的属性都能拦到, 代码也短。
**否决**: 代理会改变对象的**身份与行为特征** —— 站点一句
`Navigator.prototype.hasOwnProperty.call(navigator,'x')` 或 `Object.getPrototypeOf` 比对
就能看出不是原生对象, 这本身就是**最强的指纹信号**。
一个负责找指纹的工具, 不能自己制造指纹。改用原型链钩子, 只包装具体方法。

**把 fp-insight 并入 fp-audit 作为子命令。**
最强理由: 两者都跟指纹有关, 合在一起少一个顶层目录, 共用一份 Chromium 启动逻辑。
**否决**: 用途相反 —— fp-audit 会**修改环境**以达标, fp-insight **绝不改动被测对象**;
一个要"变成合格的人", 一个要"如实记录别人在看我什么"。
混在一起, 下一个人必然在某次改动里把两者的纪律搅在一起
(例如为了"让站点正常跑"而顺手改了返回值), 那会让取证结论全部失效。

## Consequences

- 新增顶层目录 `workspaces/browser-auto/fp-insight/`, 已登记 `docs/PROJECT-MAP.md`
  与 `run.sh` REGISTRY (端口 28360)。
- **四条"证据不被自己污染"的纪律**, 每条都对应实测踩过的坑 (见 README「已实测的坑」):
  探针内务走原始引用 / 单例实例用 `getPrototypeOf` / 自读冠 `env:`·`store:` 前缀 /
  栈以"首个真实 URL 帧"切分。
  这些不是风格, 是判据 —— `tests/test_inject_static.py` 逐条守着, 删掉即回归。
- **读库前必须过 `drain()` 屏障**。事件是异步回传的, 不等落盘就查会读到
  "站点什么都没采"的空快照 —— 本轮实测出现过 (154 条事件在库, 汇总却报精确读取 0),
  这是最容易被误当成结论的假象。屏障用**队列内哨兵**而非共享标志位:
  后者会让 drain 在写入线程尚未清标志时提前返回。
- 与 `fp-audit/` 互补不重叠, 路由 = browser-auto 工作区; 两者可组合成
  "先看清对方看什么 → 再保证自己那个面过关" 的闭环。
- 面板是原生 ESM + 静态文件, **无构建步骤**, 后端直接托管 —— 避免本仓库栽过的
  「Vite dev server 经子路径接入白屏」那一类问题 (见 2026-09-19-devvite-frontends-need-subpath-adapter)。
